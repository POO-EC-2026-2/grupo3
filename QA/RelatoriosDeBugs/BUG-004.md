# BUG-004 — Falha na remoção de monstro do cache

**Funcionalidade:** Exclusão de monstro  
**Classe:** `MonstroRepository.java`  
**Método:** `delete(Monstro monstro)`  
**Classe de teste:** `MonstroRepositoryTest.java`

## Descrição

Ao excluir um monstro utilizando uma instância diferente daquela armazenada no cache, o registro correspondente permanece na lista `loadedMonstros`.

O método `delete()` utiliza `loadedMonstros.remove(monstro)`, que não reconhece outra instância do mesmo registro, pois a classe `Monstro` não sobrescreve `equals()`.

## Passos para reprodução

1. Cadastrar um monstro.
2. Consultar o monstro pelo ID.
3. Confirmar que as duas instâncias são diferentes.
4. Excluir o monstro utilizando a instância original.
5. Verificar se o monstro foi removido do cache.

## Resultado esperado

O monstro excluído deve deixar de aparecer no cache, independentemente da instância utilizada na exclusão.

## Resultado obtido

O registro é excluído corretamente do banco de dados, mas a instância original permanece na lista `loadedMonstros`.

## Evidências

- `repository.loadFromId(id)` retorna `null` após a exclusão, confirmando a remoção do banco.
- A verificação `loadedMonstros.stream().noneMatch(m -> m.getId() == id)` falha, confirmando que o cache não foi atualizado.

## Status

**Corrigido**

**Foi alterado o método delete de MosntroRepository:**
- "if (monstro == null) return;" — evita um NullPointerException caso alguém chame delete(null).

- "removeIf(m -> m.getId() == monstro.getId())" — percorre o cache "loadedMonstros" e remove qualquer instância que tenha o mesmo id do monstro excluído, mesmo que seja outro objeto na memória.

- "this.loadedMonstro != null && this.loadedMonstro.getId() == monstro.getId()" — substitui "this.loadedMonstro == monstro", garantindo que "loadedMonstro" também fique null quando a exclusão for feita usando outra instância.
